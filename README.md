# CardVault

## 2.3.4 可靠性与性能修复

修复设备对话框安全弹出异常，活动任务仍禁止弹出相关设备。状态保存改用紧凑 JSON，在锁外落盘，普通检查点合并至每两秒最多一次，暂停及关键节点仍立即保存。文件级汇总只在状态变化时重算，块级进度使用缓存。每个拷贝线程复用只读哈希进程，超时、暂停或异常后重建，阶段结束后回收；摘要仍在文件关闭后才确认。目标写入、刷盘和 Windows 重命名提交接入取消检查，取消后的部分文件在恢复时重新验证。修复暂停状态被覆盖及主题色替换串色。

保留原有源文件预哈希和复制后复核，不降低校验强度。已通过 88 项测试，包括真实 Windows 阻塞读写取消、校验关闭超时、进程复用、刷盘与提交时暂停恢复。取消依赖设备驱动响应，未承诺故障设备的文件打开、关闭或写入能立即返回；不强杀写入线程。类型化记录、重复代码整理、日志清理及单次读取多目标复制留待后续。

本机合成 20,000 文件记录测试：锁内快照约 166 → 37 ms，块级汇总约 9.05 → 0.001 ms，状态 JSON 约 8.1 → 4.7 MB。这是特定样本的中位数，不代表存储卡吞吐量。Windows 发行版对本地 1 MiB 文件的哈希中位数：每次启动进程约 194 ms，复用已启动进程约 1.3 ms（20 次采样，含缓存影响）。可运行 `python packaging/benchmark_engine.py` 复测；加 `--exe 发行目录/CardVault.exe` 可测发行版哈希进程开销。

2.3.3 用户使用名称含 `from-2.3.3` 的 2.3.4 增量包；其他版本使用 Setup。旧更新器不会强制检查增量基础版本，必须选择对应版本的包。安装包与更新包始终放在项目根目录 `release/`。


## 2.3.3 发行包瘦身

精简未使用的 Qt QML、虚拟键盘、PDF 和 OpenGL 组件，保留完整思源黑体及四种界面语言。发行包统一输出到项目根目录 `release/`；即使从 `push` 运行构建，安装包、ZIP、源码 ZIP 与 `.upd` 也不会写入 `push/`。可用 `CARDVAULT_OUTPUT_DIR` 指定外部输出目录。Setup 升级会清理明确列出的旧组件；旧版 `.upd` 更新器不会清理多余旧库，如需减少已安装体积请使用 Setup 或全新解压便携包。

实测对比 2.3.2：程序目录 142.4 → 102.4 MiB，Setup 53.3 → 41.9 MiB，便携 ZIP 70.9 → 54.8 MiB。已通过精简后依赖检查、实际窗口启动与内置多目标校验测试。

已补充约 2.6 MiB 的 `CardVault-2.3.3-from-2.3.2-Windows-x64.upd` 增量升级包，**仅用于完整的 2.3.2 安装升级到 2.3.3**。在设置 → 更新中拖入；已安装 2.3.3 无需重复升级。旧更新器不强制检查增量基础版本，请勿用于其他版本或缺失文件的安装目录。增量包复用相同运行库与字体，仅替换三个有变化的文件；不会清理旧库，减少安装占用仍请使用 Setup。

制作同类增量包：保留基础版与目标版完整目录在根目录 `release/`，运行 `python packaging/build_delta_update.py --base-version 2.3.2`，再运行 `python packaging/test_update.py --base-version 2.3.2` 验证。

## 2.3.2 修复说明

修复更新后主窗口隐藏：更新器正常显示主程序，兼容旧更新器隐藏启动的情况。哈希校验改为独立只读进程，超时与暂停覆盖打开、读取和关闭文件；只有文件关闭且校验进程正常退出后才接受摘要，失败或超时不会提交副本。保留 16:9 启动窗口。通过 78 项自动化测试，包括模拟关闭文件永久阻塞时的超时与暂停。设备驱动故障仍需检查连接；程序会保留临时副本与任务进度供恢复。

## 功能亮点

| 功能 | 说明 |
| --- | --- |
| 设备与目标检查 | 识别存储设备，检查目标可写性及剩余空间 |
| 多线程复制 | 每个任务 1–8 个线程，默认 3 个；最多同时运行 3 个任务 |
| 多目标备份 | 准备页直接增删目标目录，一次复制到多个位置，支持记忆路径 |
| 校验算法 | 准备页选择 SHA-256 (Hash) 或 MD5，每个任务保存所选算法 |
| 分阶段进度 | 集中校验显示上方绿色复制进度和下方蓝色校验进度 |
| 两种校验时机 | 逐份复制后校验，或全部复制后集中校验 |
| 素材整理 | 文件类型筛选、日期分类、自定义命名、重复文件处理 |
| 错误恢复 | 失败重试、暂停和恢复任务、历史记录 |
| 实时状态 | 总进度、当前文件、复制速度与预计剩余时间 |
| 清晰报告 | 突出显示成功、失败、跳过、待处理数量，支持导出 |
| 四种界面语言 | 简体中文、繁体中文、英语、日语；首次启动按时区选择，可在设置中更改 |
| 外观设置 | 内置开源思源黑体，支持自选字体与主题色 |
| 本地更新 | 在更新页拖入专用 .upd 更新包，校验解压、替换、失败回滚并重启 |

实际复制速度由源卡、读卡器、接口和目标磁盘共同决定，增加线程不一定线性提速。

## 安装与启动

### 使用发行版

维护者发布安装包后，可在本仓库的 **Releases** 页面获取：

- `CardVault-x.x.x-Setup-x64.exe`：安装版，运行 Setup 后从快捷方式启动。
- `CardVault-x.x.x-Windows-x64.zip`：便携版，完整解压后运行 `CardVault.exe`。

**发行版无需预装 Python 或依赖库。** 便携版请保留整个文件夹及其中的 DLL、字体和其他资源，不能只复制 EXE。源码仓库本身不包含安装包。

### 从源码运行

开发环境：Windows 10/11 x64、Python 3.13 x64；已使用 Python 3.13.7 验证。在源码根目录打开 PowerShell：

```powershell
py -3.13 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe start.py
```

直接使用 Python 入口启动，不需要 BAT 或手动激活虚拟环境。安装依赖需要联网；复制、校验和任务管理在本地执行。

## 基本使用

1. 插入存储卡，选择源设备和备份目标目录。
2. 按需设置文件筛选、分类、命名和更多备份目标。
3. 在设置中选择线程数；在准备页选择校验算法及校验时机。
4. 开始备份，查看复制与校验进度。
5. 完成后查看报告，检查失败和待处理项，再进行后续素材管理。

设置中的语言修改在重启后生效；字体和主题色保存后立即应用。

## 本地 .upd 更新

在 **设置 → 更新** 中拖入版本更高的 `CardVault-版本-Windows-x64.upd`。这是包含清单、文件大小和逐文件 SHA-256 的专用 ZIP 更新格式；改名普通 ZIP 不会生成合格的更新包。

程序检查并保存更新包到 `update/`。执行更新时先暂停任务并退出；辅助进程等待退出后复核、解压全部文件，再替换应用文件。替换过程中出现错误会尝试恢复原文件并重新启动旧版。更新结果与回滚副本保存在 `update/`，任务记录及无关文件不会被覆盖。

**2.2.x 及更早版本请先通过 2.3 Setup 安装包升级一次，或使用新的便携目录。** 旧版更新页不支持 `.upd`。从 2.3 开始，更新页只接受更高版本的 `.upd`，Setup 用于首次安装。

摘要校验用于发现文件损坏，不是数字签名。请使用可信来源的更新包。MD5 选项只影响素材校验，更新包始终使用 SHA-256。

## 数据与边界

集中校验使用单线程顺序读取，复制阶段仍使用设置中的并发线程数。读取长时间没有返回时会显示设备等待状态，30 秒后请求取消并按重试策略处理；暂停也会请求取消正在等待的读取。Windows 驱动需要响应取消请求，因此不能保证故障设备能立即停止。保存任务的磁盘操作不再占用界面使用的全局锁，暂停完成状态在记录落盘后显示。

- 默认只读取源卡，不删除源文件。校验结果用于检查副本完整性，不保证存储硬件永远可靠。
- 两个目标目录若位于同一物理磁盘，不能防止该磁盘故障导致两个副本同时丢失。
- 源码运行时记录位于 `data/`；安装版默认位于 `%LOCALAPPDATA%\CardVault`。记录、报告和编译产物已在 Git 忽略规则中排除。
- 日期分类基于文件修改时间；当前不以完整保留空目录、NTFS ACL 或备用数据流为目标。
- 复制速度与预计时间不包含所有校验开销；安全弹出受 Windows 和设备占用情况限制。
